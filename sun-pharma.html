AI-powered control tower / enterprise platform

Sun Pharma · R&D Control Tower Dashboards

Designing AI-powered decision dashboards for CEOs and scientists to accelerate drug development.

Role
Senior AI Experience Designer
Industry
Pharma, Enterprise Systems, R&D
Scope
Dashboard design, decision systems, workflow visibility, AI-assisted insights

Overview

Sun Pharma's R&D organization operates across highly complex, multi-stage drug development workflows involving:

  • Scientists
  • PMOs
  • Quality teams
  • Manufacturing
  • Regulatory stakeholders

Despite strong processes, decision-making remained:

  • Delayed
  • Fragmented
  • Reactive
The core issue was not execution. It was the lack of real-time, decision-ready visibility.

I focused on designing AI-powered control tower dashboards that enable:

  • Leadership to track portfolio-level performance
  • Scientists to execute workflows efficiently
  • Teams to identify and act on risks early

The Problem

1. No unified view of projects

Critical information was scattered across:

  • SAP
  • LIMS
  • ELN
  • TrackWise
  • Spreadsheets

There was no single interface to answer:

  • What's on track?
  • What's delayed?
  • Where do we intervene?

2. Delays were reactive

Bottlenecks (like tech transfer, approvals) were:

  • Identified too late
  • Not surfaced proactively

3. Data was not actionable

While data existed, it was:

  • Disconnected
  • Not synthesized
  • Not tied to decisions

My role

I led the design of two core dashboard systems:

  • Executive Control Tower (CEO / PMO)
  • Scientist Workflow Dashboard

My focus was:

  • Structuring complex workflows into usable interfaces
  • Defining decision points across user types
  • Designing real-time visibility systems
  • Translating pharma workflows into intuitive UX
  • Creating AI-assisted insights for proactive decision-making

Dashboard 1 · Executive Control Tower

Portfolio-level decision system for leadership

Live preview · Sun Pharma CEO Dashboard Open in new tab ↗

Purpose

Enable leadership to answer:

  • Which projects are at risk?
  • Where are delays emerging?
  • What requires immediate intervention?
  • How is the portfolio performing overall?

1. Designing for decisions, not reporting

Instead of showing raw data, the dashboard surfaces:

  • Risk signals
  • Bottlenecks
  • SLA deviations
  • Critical path issues

The goal:

"Where should I act?"

2. Timeline intelligence layer

Projects are visualized through:

  • Planned vs actual timelines
  • Stage-wise delays
  • Critical path mapping

Enables proactive intervention instead of post-facto tracking.

3. Risk & escalation signals

The system highlights:

  • Early warning indicators
  • Delayed dependencies
  • Escalation triggers

Turns hidden risks into visible decisions.

4. Portfolio-level clarity

Leadership sees:

  • All projects in one view
  • Clear health indicators
  • Comparative performance

Why this matters: This dashboard transforms leadership from reactive reviewers into proactive decision-makers.

Dashboard 2 · Scientist Workflow Dashboard

Task-level execution system for scientists

Live preview · Sun Pharma Scientists Dashboard Open in new tab ↗

Purpose

Enable scientists to:

  • Know exactly what to do next
  • Understand dependencies
  • Execute tasks without coordination overhead

1. Task-centric design

Instead of abstract workflows, the interface shows:

  • Task queue
  • Required inputs
  • Clear outputs

Reduces ambiguity in execution.

2. Workflow sequencing

Tasks are:

  • Ordered logically
  • Connected to upstream/downstream dependencies
  • Automatically updated

Removes need for manual tracking.

3. Contextual information layer

Each task includes:

  • Relevant documents
  • System inputs
  • Dependencies
  • Constraints

Eliminates context switching.

4. Embedded intelligence

The system provides:

  • Alerts for delays
  • Suggested next steps
  • Dependency warnings

Supports faster execution decisions.

Why this matters: This dashboard transforms execution from manual coordination into structured, system-driven workflows.

AI in the system

AI was used to enable decision intelligence, not just automation.

Risk detection

  • Predict delays
  • Identify bottlenecks

Workflow insights

  • Highlight inefficiencies
  • Suggest improvements

Smart alerts

  • Notify before escalation

Knowledge layer

  • Surface past learnings
  • Prevent repeat issues

Reflection

This project fundamentally changed how I think about dashboards.

Most dashboards show information. This system drives decisions.

A dashboard is not a reporting tool. It is a decision-making interface.

Designing these systems required:

  • Understanding workflows deeply
  • Identifying decision points
  • Structuring information for action
